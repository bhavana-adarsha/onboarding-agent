# Handling a Rejected Claim - Runbook

## Overview

When a claim is rejected in ClaimsFlow, the Claims Ops team must investigate the root cause and take corrective action within 48 hours. Rejection reasons vary from missing documentation to coding errors to eligibility issues.

## Step 1: Identify the Rejection

Claims are automatically flagged in ClaimsFlow when a payer (insurance company) returns them with a denial code. You'll see a red "REJECTED" status on the claim detail page.

- Check the **Rejection Code** field—this indicates why the payer denied it
- Common codes: 42 (Missing EOB), 87 (Invalid Member ID), 156 (Coding Error), 203 (Out of Network)
- Document the code in the claim notes for tracking

## Step 2: Route to Appropriate Team

**For eligibility issues (codes 87, 91, 201):**
- Assign to Care Coordination team
- Tag in Slack: @care-coord-leads
- They verify member enrollment in CareBridge

**For coding/documentation issues (codes 42, 156, 178):**
- Assign to Claims Ops supervisor (currently Sarah Chen or Marcus Rodriguez)
- Note: If claim involves behavioral health codes, loop in our contracted coding auditor at External Coding Solutions

**For network/provider issues (codes 203, 267):**
- Contact Platform Engineering via Jira ticket
- They update provider network files in ClaimsFlow's backend

## Step 3: Gather Documentation

Pull the original claim submission from ClaimsFlow's document archive:
- Original claim form (CMS-1500 or 837 EDI file)
- Attached medical records or EOB
- Any prior correspondence with payer
- Member's current eligibility record from Workday integration

Save these to the claim's Confluence ticket (create one if missing, naming format: CLAIM-[Member ID]-[Date])

## Step 4: Correct and Resubmit

**For missing documents:** Attach missing EOB or medical record, then resubmit via ClaimsFlow's "Resubmit Claim" button.

**For coding errors:** Update the diagnosis/procedure codes in ClaimsFlow. Our coding guidelines are in Confluence under Claims Ops > Coding Standards v2.3. Resubmit after correction.

**For eligibility:** Verify member's plan effective date and coverage tier in CareBridge. If outdated, update Workday and sync (this happens automatically nightly, or manually via "Force Sync" in CareBridge admin panel).

## Step 5: Track and Follow Up

- Update claim status in ClaimsFlow to "RESUBMITTED"
- Create a Jira ticket: Project "CLAIMS," issue type "Rejection Follow-up"
- Assign to yourself with due date 5 business days out
- Add payer reference number and rejection code to ticket description

## Step 6: Verify Resolution

After 5 days, check ClaimsFlow for updated claim status. Payers typically respond within 3-7 business days.

- If approved: Close Jira ticket, mark claim "PAID"
- If rejected again: Escalate to Sarah Chen and create new follow-up ticket

## Escalation

Contact the Claims Ops manager (Sarah Chen, sarah.chen@meridian.local) if:
- Same claim rejected twice
- Rejection code is unclear or undocumented
- Payer is unresponsive after 10 days
