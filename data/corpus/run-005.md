# Data & Analytics Team - New Hire Onboarding Checklist

## Week 1: Access & Environment Setup

- [ ] **IT & Systems Access**
  - Submit ticket to IT via Slack #it-help-desk (reference: template "DA-NewHire-Access")
  - Request access to: GitHub (meridian-health org), Jira (DA project), Confluence (Data & Analytics space), Workday (reporting module), AWS dev environment
  - Receive laptop and MFA device; complete security training (required before any data access)
  - Add to Slack channels: #data-analytics, #platform-eng-collab, #analytics-incidents

- [ ] **Database & Tools**
  - DBA Priya Mehta will schedule 30-min walkthrough of our Snowflake instance (connection string: `analytics-prod.snowflakecomputing.com`)
  - Clone repo: `meridian-health/analytics-core` from GitHub
  - Install required tools: dbt 1.5+, Python 3.11, Tableau Desktop (license request goes through HR portal)

- [ ] **Meet Your Manager**
  - 1:1 with Data & Analytics Lead (currently Marcus Chen) to review 30-60-90 day plan
  - Discuss primary focus area: Claims data pipeline, Care Coordination metrics, or PulseBoard dashboards

## Week 2: Core Systems & Data Landscape

- [ ] **Data Architecture Overview**
  - Attend "Data Stack 101" session (runs Tuesdays 10am, next available session in Confluence calendar)
  - Review: `confluence.meridian.internal/wiki/Data-Architecture` (especially ClaimsFlow ETL diagram)
  - Our main sources: ClaimsFlow (PostgreSQL), CareBridge (MySQL), TimeTrax (custom API)
  - Staging layer in Snowflake, marts in `analytics.claims_mart`, `analytics.care_mart`, `analytics.ops_mart`

- [ ] **Existing Dashboards & Reports**
  - PulseBoard walkthrough with Analytics team (30 min)
  - Access shared Tableau workbooks in `/shared/analytics/dashboards` folder
  - Review monthly Claims Operations report (due 5th of each month) and Care Coordination KPI deck

- [ ] **Documentation & Standards**
  - Read: `confluence.meridian.internal/wiki/Analytics-Standards` (naming conventions, code review process)
  - dbt project structure explained in README at repo root
  - Jira workflow: tickets in DA project use labels `[data-request]`, `[bug]`, `[infrastructure]`

## Week 3-4: First Projects & Ongoing

- [ ] **Assigned Task**
  - First ticket typically: data validation task or documentation update (low-risk, high-context)
  - Marcus will assign initial Jira ticket; target completion by end of week 4

- [ ] **Key Contacts**
  - Claims Ops lead: Sarah Donovan (Slack: @sdonovan)
  - Platform Engineering liaison: James Wu (handles ClaimsFlow integrations)
  - Data governance: Marcus Chen reviews all new mart proposals

- [ ] **Recurring Meetings**
  - Weekly DA standup: Thursdays 9am (Slack link in channel description)
  - Monthly data governance sync: last Tuesday, 2pm
  - Bi-weekly 1:1 with manager

- [ ] **Access Verification**
  - Confirm you can query `analytics.claims_mart.claims_summary` table
  - Test Tableau connection to Snowflake
  - Verify GitHub pull request access (create test branch to confirm)
