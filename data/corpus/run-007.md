# ClaimsFlow Deployment Runbook

## Overview

This runbook covers the process for deploying code changes to ClaimsFlow, our claims processing system. Follow these steps sequentially. Deployments typically occur on Tuesdays and Thursdays between 2-4 PM ET to minimize impact on Claims Ops.

## Pre-Deployment (Day Before)

1. **Confirm the change in Jira**
   - Locate the ticket (e.g., CF-4521) in the ClaimsFlow project
   - Verify the ticket is marked "Ready for Deploy"
   - Ensure QA sign-off is documented in comments

2. **Review the GitHub PR**
   - Navigate to the `meridian-claimsflow` repository
   - Confirm all required code reviews are complete (minimum 2 approvals)
   - Check that CI/CD pipeline passed (green checkmark on all checks)

3. **Notify stakeholders**
   - Post in #claimsflow-deploys Slack channel: "@Claims Ops Team - Deploying CF-4521 tomorrow at 2 PM. Expected downtime: 15 minutes."
   - Include a brief description of the change

## Deployment Day

4. **Merge to main branch**
   - In GitHub, click "Squash and merge" on the approved PR
   - Use commit message format: `[CF-4521] Brief description of change`
   - Delete the feature branch after merging

5. **Trigger the deployment pipeline**
   - Go to GitHub Actions in the `meridian-claimsflow` repo
   - Select the "Deploy to Production" workflow
   - Click "Run workflow" and select `main` branch
   - The pipeline will automatically build, test, and deploy to our AWS environment

6. **Monitor the deployment**
   - Watch the workflow run (typically 8-12 minutes)
   - Check PulseBoard for any error spikes in the Claims Processing dashboard
   - Monitor Slack #platform-alerts for infrastructure warnings

7. **Verify in production**
   - Log into ClaimsFlow production environment
   - Test the specific feature modified (e.g., if claim status updates changed, process a test claim)
   - Confirm no error logs in CloudWatch

## Post-Deployment

8. **Update Jira**
   - Move the ticket to "Deployed to Production"
   - Add a comment with deployment timestamp and any notes

9. **Communicate completion**
   - Post in #claimsflow-deploys: "CF-4521 deployed successfully at [time]. Monitoring for issues."

10. **Monitor for 2 hours**
    - Stay available for rollback if needed
    - Check Claims Ops dashboards periodically
    - Watch for ticket volume anomalies in Slack

## Rollback Procedure

If critical issues arise:

1. Post `@here` alert in #platform-alerts
2. In GitHub Actions, run the "Deploy to Previous Release" workflow
3. Select the previous stable build from the dropdown
4. Update Jira ticket to "Rolled Back"
5. Document root cause in ticket comments

## Escalation

For deployment failures or unclear errors, contact Platform Engineering on-call via Slack or page via PagerDuty (if after hours).
